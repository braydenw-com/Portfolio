## intro title
Make your own design system

## intro summary
**You don’t need a 200-component library.** You need a short list of colors, type styles, and parts that you actually use, with names you’ll remember. Here’s how I built the one behind this site.

## start label
01 · Start

## start heading
Start with what you already use.

## start paragraph
Before picking anything new, look at your own pages. Write down every color, font size, and repeated part. Most of the system is already there, just unnamed.

## start do title
From my site

## start do text
I didn’t invent a palette. I measured every page and found 7 colors and 9 text styles doing all the work. Those became the system.

## start skip title
Skip

## start skip text
A palette from a mood board that doesn’t match anything you’ve made.

## colors label
02 · Colors

## colors heading
Keep the palette small.

## colors paragraph
Give every color a job: text, quiet text, lines, backgrounds, and one accent. If two colors do the same job, keep one.

## colors do title
From my site

## colors do text
Seven colors, and only one is loud. Brayden Blue is for my name, focus rings, and hover states. Everything else stays quiet so the work stands out.

## colors skip title
Skip

## colors skip text
Twelve shades of every color “just in case.” Unused colors turn into inconsistent ones.

## type label
03 · Type

## type heading
Two typefaces, each with a job.

## type paragraph
Pick one typeface for headlines and one for everything else. Then name each size by where it’s used, not by its pixel value.

## type do title
From my site

## type do text
Instrument Sans for headlines, Geist for the rest. Nine styles, from Tall Order for my name to Name Tag for the little labels on cards. Each one scales down on phones.

## type skip title
Skip

## type skip text
A new font size every time a page feels off. Fix the style instead.

## names label
04 · Names

## names heading
Name tokens so you remember them.

## names paragraph
A token is a named value you can reuse in code, like a color or a text style. Good names make the system easy to talk about and fun to use. Change the value once and it updates everywhere.

## names do title
From my site

## names do text
Brayden Blue is --color-brayden-blue in the stylesheet. Section headings use Idea Stroll. When I changed a token, every page followed.

## names skip title
Skip

## names skip text
Names like blue-500 or heading-2. They say nothing about how the color or style is used.

## components label
05 · Components

## components heading
Show the real thing.

## components paragraph
Document your components with the same code the site uses, so the documentation can’t drift. Let people click them.

## components do title
From my site

## components do text
My design system page uses the real nav, tags, links, and project cards. You can click the nav to see its states, and nothing navigates away.

## components skip title
Skip

## components skip text
Static mockups of components. The day you change the real one, the docs are wrong.

## takeaway label
The takeaway

## takeaway heading
Your portfolio is your first design system.

## takeaway paragraph
Building one for your own site teaches the same things a team system does: name what matters, use it everywhere, and keep it small enough to remember. [See mine](/design-system).
